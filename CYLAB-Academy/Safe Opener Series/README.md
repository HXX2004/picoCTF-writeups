# 在Safe Opener中學到了什麼?
1. **Base64 是編碼，不是加密：** 不需要金鑰就能解碼。如果程式直接儲存 Base64 編碼後的密碼，就可能被還原。
2. **追蹤資料的處理流程：** 從 `encoder.encodeToString()` 可以知道使用者輸入會先被編碼，再進行比較。
3. **分析驗證邏輯：** `password.equals(encodedkey)` 表示程式最後比較的是編碼後的字串，因此可以從固定的 `encodedkey` 反向推導原始密碼。
4. **先找關鍵線索再解題：** 不需要直接猜密碼，先觀察程式使用了哪些編碼方式，以及固定字串如何被使用，就能縮小分析方向。
# 在Safe Opener 2 中學到了什麼?
1. **反編譯（Decompilation）：** 將編譯後的程式還原成可讀性較高的原始碼形式。
2. **靜態分析：** 不必執行程式，就能透過閱讀程式碼理解其邏輯。
3. **硬編碼敏感資訊：** 將密碼或 flag 直接寫在程式中，可能讓取得程式檔案的人輕易讀取。
4. **這題最重要的觀念：** 當題目提供編譯後的程式檔案，並提示你進行反編譯時，應該先還原程式碼，再追蹤關鍵函式與比較條件，而不是只搜尋二進位檔中剛好可讀的字串。
